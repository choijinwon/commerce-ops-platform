# Architecture Notes

## 제품 관점

Commerce Ops는 운영자가 여러 판매 채널의 상태를 빠르게 파악하고 예외를 처리하는 working surface입니다. 핵심 사용자 흐름은 다음과 같습니다.

1. 대시보드에서 비정상 신호 발견
2. 관련 주문·재고·정산 화면으로 이동
3. 검색과 필터로 대상 축소
4. 주문 상태 변경 또는 후속 업무 시작
5. 화면 피드백으로 처리 결과 확인

## 프론트엔드 구조

```text
app/
  layout.tsx             전역 메타데이터와 폰트
  page.tsx               애플리케이션 진입점
components/
  commerce-ops-app.tsx   화면 조합, 사용자 상태와 업무 흐름
  ui/                    접근성을 갖춘 공용 인터페이스 프리미티브
lib/
  commerce-data.ts       도메인 타입과 데모 데이터
  utils.ts               공용 스타일 유틸리티
```

도메인 데이터와 표현 계층을 분리해 API 연결 시 `lib/commerce-data.ts`를 서버 응답 모델로 교체할 수 있게 했습니다. 주문 상태는 `OrderStatus` 유니언으로 제한해 잘못된 상태 전이를 컴파일 단계에서 줄입니다.

## 상태 관리 판단

이 데모의 상태는 주문 목록, 검색, 필터, 선택 화면에 한정됩니다. 서로 복잡하게 얽힌 전역 상태가 아니므로 별도 상태 관리 라이브러리 대신 React state와 파생 값(`useMemo`)을 사용했습니다.

서버 API가 추가된다면 다음 순서로 확장합니다.

- TanStack Query로 서버 캐시와 optimistic mutation 관리
- 주문 상태 변경 API에 idempotency key 적용
- 검색·필터를 URL query parameter와 동기화
- 실시간 주문은 SSE 또는 WebSocket으로 수신
- 역할 기반 접근 제어와 감사 로그 추가

## 성능 전략

- 검색과 상태 필터 결과는 원본 주문에서 파생해 불필요한 복제 상태를 만들지 않습니다.
- 아이콘은 단일 아이콘 라이브러리에서 tree-shaking 가능한 형태로 가져옵니다.
- 대량 주문 목록에서는 서버 페이지네이션과 TanStack Virtual을 적용할 수 있도록 표 영역을 독립적으로 구성했습니다.
- 첫 화면에 대표 운영 데이터가 즉시 표시되고, 불필요한 마케팅 영역이나 대형 이미지를 로드하지 않습니다.

## 접근성

- 주요 영역에 시맨틱 헤딩, 내비게이션, 표 요소를 사용했습니다.
- 모바일 메뉴와 검색, 상태 변경 컨트롤에 접근 가능한 이름을 제공합니다.
- 상태는 색상뿐 아니라 텍스트로도 구분합니다.
- 키보드에서 `⌘/Ctrl + K`로 통합 검색에 접근할 수 있습니다.

## WebMCP

지원 브라우저에서는 다음 도구를 노출합니다.

- `filter_orders`: 검색어를 적용하고 주문 관리 화면에 결과 표시
- `mark_order_ready_to_ship`: 주문번호로 주문 상태를 출고 준비로 변경

두 도구 모두 사람이 사용하는 동일한 React 상태와 업무 동작을 공유합니다.
